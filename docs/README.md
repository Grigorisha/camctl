# Документация проекта camctl

Сервис для запуска и управления обычными и тепловыми камерами.

Эта папка — рабочее пространство документации: сюда складываются мысли, решения,
архитектурные размышления, план работ и черновики, из которых потом собирается
итоговая документация.

## Как вести документацию

Короткий регламент, чтобы документация не превращалась в свалку:

- **Мысли и ежедневный прогресс** → в [07-journal/](07-journal/), один файл на дату
  (`YYYY-MM-DD.md`). Это «черновик ума»: что сделал, что решил, где застрял.
- **Значимое архитектурное решение** (выбор протокола, библиотеки, структуры данных,
  способа синхронизации камер и т.п.) → отдельный ADR в
  [02-architecture/decisions/](02-architecture/decisions/). Решение, о котором
  захочется вспомнить «почему мы так сделали», обязано стать ADR.
- **Проверка гипотезы / замер** → протокол в
  [06-research/experiments/](06-research/experiments/) по шаблону.
- **Стабильное знание** (требование, описание компонента, формат кадра, особенность
  камеры) → в соответствующий тематический раздел. Из этих разделов потом собирается
  итоговая документация.

Поток обычно такой: сырая мысль в журнале → если оформилась в решение, оно
переезжает в ADR или тематический раздел.

### Статусы документов

Каждый документ начинается с шапки-статуса:

```
> Статус: черновик | в работе | утверждён
> Обновлён: 2026-06-26
> Автор: <имя>
```

- **черновик** — наброски, может быть неполным и противоречивым;
- **в работе** — активно дополняется, в целом отражает текущее понимание;
- **утверждён** — стабильно, на это можно опираться; менять через осознанное решение.

### Соглашения

- **Имена файлов и папок — латиницей (ASCII), содержимое — на русском.** Это убирает
  проблемы с кодировкой путей и автодополнением.
- Папки пронумерованы (`00-`, `01-`, …) для предсказуемого порядка.
- Диаграммы — по возможности `mermaid` прямо в markdown (см.
  [02-architecture/diagrams/](02-architecture/diagrams/)).
- Связывайте документы относительными ссылками — так навигатор остаётся живым.

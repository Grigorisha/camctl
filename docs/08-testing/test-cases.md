## Результаты прогонов (2026-07-10)

Прогон по прямому Ethernet, тестовая камера Daheng ME2P-2621-15U3C на Jetson Orin.
Инструмент замера — `tools/tune_viewer.py`. Подробные измерения и таблицы —
в [эксперименте 2026-07-10](../06-research/experiments/2026-07-10-latency-fps-tuning.md).

- **TC-10 (поток):** h264 Constrained Baseline, вход 5120×5120 → даунскейл 1280×1280, 0 ошибок
  декодирования (после добавления `sprop-parameter-sets` в SDP и форс-IDR на входе клиента).
- **TC-11 (управление):** 8 ручек (`bitrate`, `enc_width/height`, `fps`, `exposure_us`,
  `auto_exposure`, `gain`, `decimation`) с диапазонами; `set bitrate=999` отклонён
  (`out of range`); обмен часами RTT ~0.6 мс.
- **TC-12 (reconfig):** стресс — битрейт 1↔8 Мбит, разрешение 640/960/1280 многократно, fps 15↔30 —
  без крашей (после фикса: старый NVENC уничтожаем до создания нового, чистый EOS-останов).
- **TC-13 (камера):** децимация 1→2→4 даёт сенсор 5120→2560→1280, FPS 6.1→20→20.
- **TC-14 (задержка):** glass-to-glass стабильна; децимация 320→123→106 мс; разрешение
  энкодера 480→1280 = 94→123 мс; **битрейт на задержку не влияет** (~109 мс на всём диапазоне).
  Замечание: часы меряем по `CLOCK_MONOTONIC` — реальные часы Jetson шагает NTP.
- **TC-15 (пресеты):** `presets/{indoor,outdoor,custom}.json`; `list_presets` → имена;
  `load_preset indoor/outdoor` применяет значения (подтверждено `stats`); отсутствующий пресет →
  ошибка; `save_preset` создаёт файл; стартовый пресет применяется при запуске сервиса.

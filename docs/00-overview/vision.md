## Проблема и контекст

*Какую задачу решает camctl? Почему существующих решений недостаточно?*

`camctl` разрабатывается как ПО для управления камерами, подключёнными к Jetson. В целевой конфигурации система должна работать с тремя камерами: двумя RGB/промышленными камерами Daheng ME2P-2621-15U3C и одной тепловой камерой. Две RGB-камеры образуют стереопару и используются для последующей оценки глубины кадра. Точная модель тепловой камеры будет зафиксирована отдельно: TBD.

Система должна получать изображения с камер, при необходимости сжимать их и
передавать внешнему клиентскому приложению по Ethernet. Так как Ethernet-канал
имеет ограниченную пропускную способность, протокол передачи должен быть
достаточно компактным и не создавать лишней нагрузки на сеть.

Существующее решение на ROS2 признано неподходящим для этой задачи, потому что
оно создаёт избыточные накладные расходы при передаче изображений. `camctl`
должен обеспечить сопоставимый прикладной результат — управление камерами и
передачу кадров — без лишних компонентов, не нужных для этой задачи.

Отдельное требование проекта — надёжная работа во внештатных ситуациях. Система
не должна аварийно завершаться при отключении камеры, ошибке SDK, потере связи с
клиентом или ошибке передачи. Для таких ситуаций должны быть определены
процедуры обнаружения, уведомления клиента и восстановления работы, если
восстановление возможно.

## Цель

*Одно-два предложения: чем проект станет, если всё получится.*

`camctl` должен стать сервисом на Jetson, который управляет двумя RGB-камерами
стереопары и одной тепловой камерой, получает с них кадры, при необходимости
сжимает изображения и передаёт их клиентскому приложению по Ethernet с
контролируемой задержкой.

Проект также должен определить протокол взаимодействия между клиентом и сервером
и набор проверок, подтверждающих корректную работу системы в штатных и
внештатных ситуациях.

## В scope

*Что точно входит в проект.*

- Управление двумя RGB/промышленными камерами Daheng ME2P-2621-15U3C
- Управление одной тепловой камерой через USB3.0 SC-SDK / plug617
- Получение кадров и потоков кадров с камер
- Одновременная работа с двумя RGB-камерами стереопары и одной тепловой камерой
- Настройка параметров захвата: разрешение, FPS, экспозиция, усиление,
пиксельформат и другие поддерживаемые параметры
- Опциональное сжатие изображений перед передачей клиенту
- Передача кадров или потоков кадров клиентскому приложению по Ethernet
- Протокол управления параметрами камер через Ethernet
- Сообщение клиенту о состоянии камер, ошибках и восстановлении работы
- Эксперименты и проверки надёжности для штатных и внештатных сценариев

## Не в scope (не-цели)

*Что сознательно НЕ делаем — чтобы не расползался объём.*

- Графический интерфейс оператора
- Алгоритмы компьютерного зрения: детекция, классификация, трекинг объектов
- Вычисление карты глубины на стороне `camctl`, если эта обработка выполняется
внешним клиентским приложением
- Хранение видеоархива или долговременная запись потоков на диск
- Полная замена ROS2 во всех задачах проекта
- Разработка драйверов камер с нуля, если производитель предоставляет рабочий SDK
- Калибровка и регистрация камер как отдельная функциональность, если это не
требуется для передачи кадров
- Управление оборудованием, не связанным с захватом и передачей изображений

## Пользователи и сценарии

*Кто и как будет пользоваться сервисом.*

В этом разделе пользователь — не обязательно человек. Пользователем может быть
внешнее клиентское приложение, оператор или сервис мониторинга. Сценарий
описывает типовой способ использования системы: кто обращается к camctl, какую
задачу решает и какой результат должен получить.

В базовой модели camctl работает на Jetson как сервер: он управляет камерами,
получает с них кадры и отдаёт данные по Ethernet. Программа, которая запрашивает
изображения или меняет параметры камер, выступает клиентом.


| Пользователь                                | Сценарий                                                                                                                                       | Что получает                                                                                  |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Клиентское приложение                       | Подключается к camctl по Ethernet и запрашивает поток с выбранной камеры с заданными параметрами: разрешение, FPS, формат кадра и режим сжатия | Поток кадров с нужными параметрами                                                            |
| Оператор / инженер                          | Настраивает параметры камеры через Ethernet: экспозицию, усиление, разрешение, FPS и другие доступные параметры                                | Подтверждение применения настроек и актуальное состояние камеры                               |
| Клиентское приложение                       | Одновременно запрашивает изображения с двух RGB-камер стереопары                                                                               | Параллельные потоки RGB-кадров с известными временными метками для последующей оценки глубины |
| Клиентское приложение                       | Запрашивает изображение с тепловой камеры                                                                                                      | Поток тепловых кадров в поддерживаемом формате                                                |
| Система мониторинга / клиентское приложение | Получает уведомление о внештатной ситуации: камера отключена, поток остановлен, превышена задержка или произошла ошибка передачи               | Код ошибки, описание проблемы и текущее состояние восстановления                              |
| Клиентское приложение                       | После сбоя повторно подключается к camctl                                                                                                      | Возобновлённый поток или понятная ошибка, если восстановление невозможно                      |


## Критерии успеха

*По каким признакам поймём, что цель достигнута (измеримо, если возможно).*

- Клиентское приложение может подключиться к `camctl` по Ethernet и получить
поток кадров с выбранной камеры.
- Клиент может задать поддерживаемые параметры камеры и получить подтверждение,
что настройки применены или отклонены с понятной причиной.
- Если клиент не задал параметры камеры явно, `camctl` использует
документированные значения по умолчанию.
- Клиент получает кадры в запрошенном разрешении, формате и с заданной частотой
кадров в пределах возможностей камеры и сети.
- Система поддерживает одновременную работу трёх камер: двух RGB-камер Daheng
ME2P-2621-15U3C и одной тепловой камеры.
- Задержка передачи кадров контролируется и измеряется; целевое значение будет
определено после экспериментов: TBD мс.
- При отключении камеры, потере связи с клиентом или ошибке передачи `camctl` не
завершается аварийно и сообщает клиенту состояние ошибки.
- После восстановления камеры или клиентского соединения система может
возобновить работу без перезапуска всего сервиса, если это поддерживается
оборудованием и SDK.

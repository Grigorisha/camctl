# Журнал архитектурных решений (ADR)

> Статус: в работе
> Обновлён: 2026-06-26
> Автор:

**ADR (Architecture Decision Record)** — короткая запись об одном значимом решении:
что решили, в каком контексте и почему. Цель — чтобы спустя месяцы можно было понять
«почему мы так сделали» и не переоткрывать уже закрытые вопросы.

## Когда заводить ADR

Заводите ADR, когда решение:

- влияет на структуру системы или её ключевые свойства (производительность, надёжность);
- выбирает между несколькими вариантами (библиотека, протокол, формат данных, язык);
- трудно или дорого отменить позже;
- о нём наверняка спросят «почему?».

Мелкие, легко обратимые решения в ADR не нужны — для них хватает журнала
[../../07-journal/](../../07-journal/).

## Как вести

1. Скопируйте [adr-template.md](adr-template.md) в новый файл
   `NNNN-краткое-название.md` (номер — следующий по порядку, латиницей).
2. Заполните поля, выставьте статус.
3. Добавьте строку в индекс ниже.
4. Если решение отменяет прежнее — поставьте старому статус «заменено» и сошлитесь на новое.

**Статусы ADR:** `предложено` → `принято` → (`заменено` | `отклонено`).

## Сделано

- Единый просмотрщик `viewer_qt.py`: 2 Daheng (gxipy) + тепловизор в одном Qt-окне —
  воркеры в потоках, рендер по таймеру, авто-переподключение, панель параметров Daheng.
- Тепловизор встроен через ctypes-обёртку `guide_thermal.py` + `libGuideUSBCamera.so`
  (собрана из вендорской `.a` через `--whole-archive`). OpenCV на этой камере зависает —
  от `cv2.VideoCapture` отказались.
- **Развёртывание на Jetson (aarch64)**: установлены ARM-версии Galaxy SDK и Guide SDK,
  пересобрана `.so`; все три камеры работают (Daheng — 12/12 кадров 5120×5120, тепловизор —
  198 кадров + температуры). Добавлены `requirements.txt` и `setup_jetson.sh`, раздел в
  [../09-operations/deployment.md](../09-operations/deployment.md).
- Авто-выбор Bayer-формата (ME2P → GB8, NS-301 → RG8) — раньше жёсткий RG8 ронял ME2P.
- Ограничение полосы USB (`DeviceLinkThroughputLimit`, FPS-cap) против неполных кадров.

## Решения

- Транспорт видео: RTSP/RTP + H.264 через `ffmpeg` —
  [../02-architecture/decisions/0002-streaming-transport.md](../02-architecture/decisions/0002-streaming-transport.md).
- Тепловизор в приложении — через C-SDK (ctypes-обёртка), не через OpenCV/V4L2.
- **Язык релиза — C++** (максимальный контроль и скорость ради низкой задержки); Python —
  только прототип для проверки камер.
  [ADR-0003](../02-architecture/decisions/0003-service-language-cpp.md).

## Проблемы / застряло

- GUI по обычному SSH не открывается (`could not connect to display :0`) — запускать в
  графической сессии Jetson (монитор / NoMachine), либо `xhost` + `DISPLAY=:0`.
- Стриминг (RTSP/RTP/H.264) и JSON-пресеты пока только в требованиях, не реализованы.
- Совмещение RGB ↔ тепло (калибровка) — открытый вопрос.

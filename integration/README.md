# camctl — API для интеграции (минимальный набор)

## 1. Что есть на сервере

Одна физическая машина (Jetson) держит несколько камер. Каждая камера — это
**отдельный процесс со своей парой портов**:


| Камера    | Что это                | RTSP-порт (видео) | Control-порт (управление) |
| --------- | ---------------------- | ----------------- | ------------------------- |
| `cam0`    | Daheng NS-301UCL (RGB) | 8554              | 8555                      |
| `cam1`    | Daheng NS-301UCL (RGB) | 8556              | 8557                      |
| `thermal` | PLUG617R (тепловизор)  | 8558              | 8559                      |


Адрес сервера в вашей сети: `192.168.1.109`.

Камеры полностью независимы: можно подключаться к любой подсети портов отдельно,
падение/перезапуск одной камеры не влияет на другие (изоляция на уровне процесса).

## 2. Видео (RTSP / H.264)

URL: `rtsp://<адрес>:<rtsp-порт>/cam0` (последняя часть пути всегда `cam0`,
независимо от реального имени камеры — это просто путь ресурса на RTSP-сервере).

```
rtsp://192.168.1.109:8554/cam0   # cam0
rtsp://192.168.1.109:8556/cam0   # cam1
rtsp://192.168.1.109:8558/cam0   # thermal
```

**Важно: сервер поддерживает только UDP-транспорт RTSP, не TCP-interleaved.**
Если ваш клиент/библиотека по умолчанию пытается TCP, получите ошибку вида
`Nonmatching transport in server reply` — явно укажите UDP-транспорт.

Примеры:

- ffmpeg/ffplay: `-rtsp_transport udp`
- GStreamer: `rtspsrc protocols=udp`
- Большинство RTSP-клиентских библиотек имеют параметр `transport=udp`/аналог —
ищите его, если подключение не идёт.

Кодек — H.264 (Baseline/Main, зависит от камеры), стандартный RTP-payload.
Несколько одновременных клиентов на одну камеру поддерживаются (проверено —
можно смотреть с двух и более устройств/окон параллельно без конфликта).

Разрешение и FPS каждой камеры — см. `stats` в п.4; типично 1280×960@~20-30fps
для RGB-камер, 640×512@25fps для тепловизора (настраивается, см. параметры).

## 3. Управляющий канал (TCP + JSON)

Протокол **не HTTP** — обычный TCP-сокет, построчный JSON: одна JSON-строка на
запрос, одна JSON-строка на ответ, разделитель — символ `\n`.

```
подключение → TCP на <адрес>:<ctrl-порт камеры>
запрос       → {"cmd":"...", ...}\n
ответ        → {"ok":true|false, ...}\n
```

Соединение можно держать открытым и слать много запросов подряд (keep-alive),
можно и переподключаться на каждый запрос — сервер поддерживает оба варианта,
несколько одновременных клиентов на один control-порт тоже разрешены.

### Команды


| `cmd`        | Параметры запроса | Что делает                                                                   |
| ------------ | ----------------- | ---------------------------------------------------------------------------- |
| `get_params` | —                 | список всех параметров камеры: имя, тип, диапазон/варианты, текущее значение |
| `get`        | `name`            | текущее значение одного параметра                                            |
| `set`        | `name`, `value`   | изменить параметр                                                            |
| `stats`      | —                 | телеметрия: fps, разрешение, битрейт, (для thermal — температуры)            |
| `time`       | `t1`              | обмен часами (см. п.6, если нужна синхронизация задержки)                    |




### Примеры

```jsonc
// запрос
{"cmd":"get_params"}
// ответ (cam0/cam1, сокращённо)
{"ok":true,"params":[
  {"name":"bitrate","type":"int","unit":"bps","value":6000000,"min":100000,"max":50000000},
  {"name":"enc_width","type":"int","value":1280,"min":160,"max":4096},
  {"name":"enc_height","type":"int","value":960,"min":160,"max":4096},
  {"name":"fps","type":"int","value":30,"min":1,"max":60},
  {"name":"exposure_us","type":"float","unit":"us","value":20000,"min":20,"max":200000},
  {"name":"auto_exposure","type":"bool","value":true},
  {"name":"gain","type":"float","unit":"dB","value":8.9,"min":0,"max":24},
  {"name":"decimation","type":"int","value":1,"min":1,"max":8}
]}
```

```jsonc
// запрос
{"cmd":"get","name":"bitrate"}
// ответ
{"ok":true,"value":6000000}
```

```jsonc
// запрос — число передаётся как есть
{"cmd":"set","name":"bitrate","value":8000000}
// запрос — bool
{"cmd":"set","name":"auto_exposure","value":false}
// запрос — enum/строка (у thermal), значение в JSON-кавычках
{"cmd":"set","name":"palette","value":"ironbow"}
// ответ на успешный set
{"ok":true}
// ответ при недопустимом значении (см. min/max/options в get_params)
{"ok":false,"error":"out of range [20.000000..200000.000000]"}
```

```jsonc
// запрос
{"cmd":"stats"}
// ответ (thermal — обратите внимание на temps_c)
{"ok":true,"stats":{
  "name":"thermal","type":"thermal","fps":25.04,
  "enc_width":640,"enc_height":512,"enc_fps":25,"bitrate":6000000,
  "decimation":1,
  "temps_c":{"hot":41.7,"cold":37.3,"cursor":38.4,"mean":38.5}
}}
```



## 4. Параметры по типу камеры

Общие (`cam0`, `cam1`, `thermal`):


| Параметр                  | Тип      | Диапазон         | Эффект                                                                              |
| ------------------------- | -------- | ---------------- | ----------------------------------------------------------------------------------- |
| `bitrate`                 | int, bps | 100000..50000000 | применяется сразу, без прерывания потока                                            |
| `enc_width`, `enc_height` | int      | 160..4096        | изменение разрешения выдаваемого видео (короткая пересборка энкодера, доли секунды) |
| `fps`                     | int      | 1..60            | то же, пересборка энкодера                                                          |


Только `cam0`/`cam1` (Daheng, RGB):


| Параметр        | Тип       | Диапазон                                                      | Эффект                                                     |
| --------------- | --------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| `exposure_us`   | float, µs | 20..200000                                                    | выдержка; ставит `auto_exposure=false` автоматически       |
| `auto_exposure` | bool      | —                                                             | автоэкспозиция вкл/выкл                                    |
| `gain`          | float, dB | 0..24 (реальный диапазон зависит от камеры, см. `get_params`) | усиление сенсора                                           |
| `decimation`    | int       | 1..8                                                          | биннинг сенсора (уменьшает физическое разрешение и полосу) |


Только `thermal`:


| Параметр  | Тип           | Значения                           | Эффект                                         |
| --------- | ------------- | ---------------------------------- | ---------------------------------------------- |
| `palette` | enum (строка) | `"gray"`, `"ironbow"`, `"rainbow"` | цветовая палитра превью, применяется мгновенно |


`gray` — оттенки серого (по умолчанию). `ironbow` — тёмно-синий/фиолетовый (холодно)
→ красный/оранжевый → жёлто-белый (горячо), классическая палитра для поиска
аномалий. `rainbow` — тот же диапазон плюс зелёный посередине, лучше показывает
мелкие перепады температуры в однородной сцене.

Диапазоны выше — реальные ограничения сервиса (защита от вырожденных значений,
которые могут сделать поток непригодным); `get_params` всегда возвращает точные
текущие `min`/`max` для конкретной камеры — ориентируйтесь на них, а не на цифры
в этой таблице, если они разойдутся.

## 5. Коды ошибок

Ответы всегда содержат `"ok":true|false`. При `false` есть `"error"` — текстовое
сообщение (не структурированный код), типичные причины:

- `unknown cmd: ...` — опечатка в имени команды.
- `unknown param: ...` — параметр с таким именем не существует у этой камеры
(например, `palette` у Daheng или `exposure_us` у thermal).
- `out of range [min..max]` — значение вне допустимого диапазона.
- `missing name` / `missing name/value` — не хватает обязательных полей запроса.



## 6. Замер задержки (опционально, для продвинутой интеграции)

Каждый H.264-кадр несёт SEI NAL (`user_data_unregistered`) с меткой времени  
захвата: 16-байтный ASCII UUID `CAMCTL-TS-0001!!`, затем 8 байт — время захвата  
в наносекундах (`CLOCK_MONOTONIC`, big-endian). Если ваш UI хочет показывать  
сквозную задержку "камера → экран", можно доставать эту метку из потока и  
сравнивать с локальным `CLOCK_MONOTONIC` с поправкой на смещение часов,  
получаемое через `{"cmd":"time","t1":<локальное_время_нс>}` → ответ содержит  
`t2`/`t3` (время на сервере), считается как в NTP (Round-trip/2 + сдвиг).  
Это не обязательно для базовой интеграции — только если нужна метрика задержки.
